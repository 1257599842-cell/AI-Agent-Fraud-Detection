## 两套训练口径（必须分开讲，否则像自相矛盾）

| | 线下评估（项目主线） | 提交版 |
|---|---|---|
| 切分 | 时间切分 `fit<125` + **21 天 embargo** + `test≥146` | **全量 train 重训**，无切分 |
| 轮数 | val 窗早停 | 沿用线下已定的 300 轮，**不在 test 上调任何东西** |
| 目的 | **不骗自己**（诚实估计线上表现） | **让别人能复核** |

两个目的不同，口径就该不同。线下报的 ROC-AUC 0.9306 与这里的私榜 0.9137 **不是同一个数**，
不能互相替代，也不构成矛盾。

## 叙事红利：比赛的时间结构与本项目的防泄漏设置天然一致

下载后实测：

- train 覆盖 **day 0–181**，test 覆盖 **day 212–394**
- **test 完全位于 train 之后，且中间隔了约 31 天**

也就是说，官方 test 不只是「未来」，还自带一个**约一个月的间隔**——
与本项目线下采用的「时间切分 + 21 天 embargo」结构**是同一种形态**。

→ **防泄漏设置不是为了报告好看，它和比赛的真实时间结构是对齐的。**
一个用随机切分调出来的模型，在这种结构上就会掉下去。

## 一处值得记的观察（含推断，已标注）

**Public 0.939 → Private 0.914，掉了 0.025。**

若该赛题的公私榜是**按时间切分**的（私榜取更靠后的时段），这个落差就是又一次
「**新鲜度衰减**」——与线下 embargo 实验测到的方向一致（线下：停训 21 天，
PR-AUC 净损失 −0.037，其中数据量因素 ≈0）。

⚠️ **但我没有核实该赛题公私榜的切分规则**（随机切分也可能产生落差，只是通常小得多）。
所以这条**记为「与已有发现方向一致的观察」，不是结论**。

## 复现

```bash
python -m src.model.kaggle_submit --prepare   # 下 test_* 并与 train 拼接
python -m src.model.kaggle_submit --train     # 全量重训 + 预测
python -m src.model.kaggle_submit --submit    # 提交（只跑一次）
```

**提交前做过的校验（都在花掉那一次之前）**：
1. 因果图特征函数在**全量已知标签**下**逐列复现** `graph_features.parquet` → 口径没漂；
2. 遮蔽末 20% 标签模拟「test 段无标签」→ 标签型特征未塌成 0/NaN（非空 98.9%）；
3. 拼接后 434 列**无任何一侧全空的列** → `id-01`→`id_01` 改名与 merge 均正确；
4. 提交文件与官方 `sample_submission.csv` **列名/行数/TransactionID 全等**，0 个 NaN。

> 第一次提交因系统代理导致上传中断（`Connection reset by peer`，14MB 文件传了 40MB 仍失败）。
> **先查 `submissions` 确认未登记**，确认那一次没被消耗掉，才重试——
> 「只提交一次」这条纪律，前提是能确认哪一次真的算数。
