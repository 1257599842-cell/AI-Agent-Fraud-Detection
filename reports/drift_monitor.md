## 结论（按实际数字）
- 末窗 ROC-AUC 0.8971 vs 基线 0.8911（Δ +0.0060）。
- 监控盯**分窗表现衰减**（而非整体欺诈率）：欺诈率列波动明显但聚合稳，印证 ⑩「波动/分布型漂移」。
- 触发器：窗口 ROC-AUC 跌破 基线−δ 即告警「该重训/近窗重校准」——这就是 ③⑩ 那条控制回路的监控端。
- 波动幅度：ROC-AUC 0.0370、PR-AUC **0.1601**（PR 区间 [0.4555, 0.6156]）。
- **PSI（模型分分布稳定性）**：各窗相对首窗（基准）的 PSI 最大 **0.0121**、末窗 0.0039（银行阈值：<0.10 稳定 / 0.10–0.25 轻微 / >0.25 显著）。分箱切点**只在基准窗定一次**，后续窗沿用——每窗各自等频分箱会让占比恒为 1/n、PSI 恒等于 0，监控就成了摆设。

> ### 为什么不选定触发指标
> **没有真退化事件 → 任何触发器的检出率都无法在真数据上验证 → 选定一个就等于声称验证过它。**
> 保留 ROC 已不可辩护（落差 1.5 SE，本数据上没有分辨力）；直接换 PR 则要辩护「6 个窗响 3 次」而那 3 次**证明不了是对的**（超量波动比 4.64× 说明含真实分布波动，而分布波动 ≠ 模型退化——本实验无干预、无结局标签，二者分不开）。
> → **两指标各自标定、并列上报，不选定。** 上方 `δ=0.02` 那一档是**历史拍定值，保留仅为可追溯，不代表被选中**。

> ### ⚠️ 为什么必须看「新增」而不是「告警」这一列
> **PR 在注入之前就已经在 3/6 个窗告警**（ROC 是 0/6）。直接看「告警」列，就分不清某个窗是**检出了注入**还是**本来就在响**。
> 所以本表以 **α=0 为参照**，另报 **「新增」= 本 α 下告警 且 α=0 下不告警**——**那才是注入的效应**。「首检」也按首个**新增**告警计。
> （执行方第一版把 `ONSET_IDX` 正好设在 PR 既有告警起点上，导致 α=0 行报出「第 1 窗检出」这种自相矛盾的读数；本列是那处缺陷的修法。同一条纪律在本项目反复出现：**判别力必须相对既有基线算，不能拿绝对命中数当功劳。**）

> **α=0 行是对照**：不注入，`新增` 两列必须都是 **0**（实测 ROC 0 / PR 0）——**这是确认注入装置本身不改变基线的自检**；若非 0，后面每一行都不可信。
> **「首检」= 从注入开始算第几个窗出现新增告警**（1 = 注入当窗即发现）。


### ⭐ 两节结论相反，而这恰好是「不选定触发指标」的实证

真数据那一节：**PR 有分辨力（落差 5.0 个 SE）、ROC 没有（1.5 个 SE）**。
本节（注入纯排序退化）：**ROC 在 α=0.05 就新增 4 个告警、注入当窗即检出；PR 在同一 α 下新增 0 个**。

> **两者不矛盾——它们回答的是两个不同的问题：**
> · 真数据那节问「**哪个指标看见了实际发生的那次下滑**」→ 答案是 PR；
> · 本节问「**哪个指标的标定后触发器会对注入的排序退化响**」→ 答案是 ROC。
>
> **机制（可从上面几张表直接读出）**：
> ① PR 的 δ 更宽（0.0364 vs ROC 0.0139），**因为 PR 本身更噪**（SE(差) 0.0182 vs 0.0069，约 2.6×）。**噪声大 → δ 必须宽 → 触发器就钝。**
> ② PR 还处在**饱和**状态：注入前它已在 3/6 个窗告警，**已经在响的窗无法再「新增」**，所以注入在那几个窗上不可能被记为检出。
>
> ### → **「敏感的指标」不等于「敏感的触发器」。**
> 指标的**分辨力**（落差 ÷ 自身噪声）和触发器的**灵敏度**（δ 相对注入效应）是两件事，**因为 δ 正是从噪声里推出来的**——一个指标越敏感地捕捉到真实波动，它的噪声就越大，标定出的 δ 就越宽，触发器反而越钝。
> → **所以「两指标并列上报、不选定」不是和稀泥**：PR 负责**看见**，ROC 的触发器负责**响**，**任何单一指标在这份数据上都被证明不够**。

> ### ⚠️ 这一节能声称什么 / 不能声称什么
> **能**：在**这种退化形态**（均匀噪声掺合，纯排序能力损失）下，标定后的检测器需要多大的 α 才有反应、以及从注入到首次**新增**告警差几个窗。
> **不能**：① **这不是「我经历过真实退化」的证据**——α 是设定的、形态是构造的，MODEL_CARD 的纪律是「合成漂移可用于检验检测器，**不得冒充真实退化**」；② **不能外推到其他漂移形态**（本注入是无结构噪声；真实概念漂移往往是「某个子群的 P(y|x) 变了」，那种形态检测难度不同）；③ 仍**未做显著性检验**，单次注入、单一随机种子。

## 结论（2026-09-28 定调：**"0 告警"描述的是尺子，不是系统**）

> **口径已由项目负责人拍板改为 PR 领衔。** 旧叙事「冻结模型半年 0 告警 = 稳定，副产物是 PR 更敏感」**作废**——它把一个**指标选择问题**说成了一个**系统稳定性结论**。
>
> **现行叙事**：冻结模型在 6 个月滚动窗上，**ROC 口径 0 次告警，而 PR 口径有 5.0 个标准误的真实落差、连续 2 窗跌破按其自身噪声标定的阈值**。两个口径指向相反，而**归一化后站得住的是 PR 那一侧**（ROC 的落差只有 1.5 个 SE，与零不可区分）。
> → 所以这份实验真正的结论不是"系统很稳"，是**"我原本选的监控指标看不见这次下滑，而我把它测出来了"**。
>
> 修订依据全部在本文件「δ 标定」节的机器区。下面逐条保留原始措辞并标注其适用口径。

- **【ROC 口径】ROC-AUC 没有跌破触发线**：7 个窗在 0.881~0.918 间波动，末窗 0.8971 甚至略高于基线 0.8911（Δ +0.006），**0 次触发**（δ=0.02）。
  ⚠️ **但"没跌破"≠"没有衰减"**：ROC 的最大落差 0.0105 只有 **1.5 个 SE**，**它既证明不了退化、也证明不了稳定**——这个口径在这份数据上**没有分辨力**。
  → 补充两条限定：**(a)** 末窗只覆盖 8/14 天、20,435 笔（数据 day 181 截断），其读数不与完整窗同尺度，**「末窗高于基线」不作结论用**；**(b)** 按 ROC 自身噪声重标 δ=0.0139（比手拍的 0.02 更严）后**仍然 0/6 告警**，所以"ROC 没跌破"这件事不是阈值太松造成的。

- **PR-AUC 更敏感——归一化后这句话从"波动更大"升级为"落差是真的"**：
  直接比 PR 落差 0.0905 vs ROC 落差 0.0105 是**混了量纲**的。除以各自 SE(差) 后：
  **ROC 落差 = 1.5 个 SE（统计上与零不可区分）；PR 落差 = 5.0 个 SE（确定是真下滑）。**
  → 所以不是"PR 抖得厉害"，是**PR 看见了一次真实的正类质量下滑，而 ROC 对它是盲的**。

- **~~"触发器工作正常且不误报"~~ 已作废。** 该表述只成立于 ROC 口径，而 ROC 口径在这份数据上没有分辨力（落差 1.5 SE）。按 PR 自身噪声标定 δ=0.0364（**比手拍的 0.02 还宽**）后，PR 仍在 3/6 个窗告警、持续性规则（连续 2 窗）下 2 次。
  → **关键点：这 3 次不能直接叫"误报"**——PR 的落差有 5.0 个 SE 的统计支撑。
  → 同时也不能直接叫"真告警"：两个指标的**超量波动比**（跨窗实测 SD ÷ 抽样 SE）分别是 ROC **2.85×**、PR **4.64×**，说明窗间差异里有超出抽样噪声的**真实分布波动**成分——而"分布波动"和"模型退化"在本实验里分不开（没有干预、没有结局标签）。

- **δ 标定只覆盖「不误报」这一半；检出率已用构造场景补上（2026-09-28）。**
  真数据 6 个窗无真退化事件 → 检出率在真数据上测不出来。已加**明确标注的合成漂移**（分数掺噪 `p'=(1−α)p+αu`，只动分数不动标签），用**同一次运行标定出的 δ** 去检。
  → **⭐ 结果与本节的真数据结论相反，而这是本轮最值钱的发现**：真数据上 **PR 有分辨力（5.0 SE）、ROC 没有（1.5 SE）**；但注入纯排序退化时 **ROC 在 α=0.05 就新增 4 个告警、注入当窗即检出，PR 新增 0**（要到 α=0.10 才新增 1 个，且延迟 4 个窗）。

  → ### **「敏感的指标」≠「敏感的触发器」**——δ 是从噪声里推出来的，指标越敏感地捕捉真实波动，它的噪声越大、δ 越宽、触发器反而越钝。
  ⚠️ 合成漂移**不是**"我经历过真实退化"的证据（α 是设的、形态是造的），且**不能外推到其他漂移形态**（本注入是无结构噪声；真实概念漂移多为"某子群 P(y|x) 变了"，检测难度不同）。单次注入、单一种子、无显著性检验。

- 不硬凑"衰减曲线"：这份数据的诚实结论是"**PR 有 5 个 SE 的真实落差，而 ROC 对它没有分辨力**"，而非戏剧性单调下滑。

## 结论的完整陈述（定调后的口径）

> *"给冻结模型做了 6 个月滚动窗监控，触发器设在 ROC 上，**0 次告警**。
> **但我没把这个当成『系统很稳』的结论**——我回头按各指标自己的抽样噪声标定了阈值（窗内自助 B=500）。
> 结果是：**ROC 的最大落差只有 1.5 个标准误，与零不可区分；同期 PR-AUC 的落差是 5.0 个标准误。**
> 直接比 0.0905 和 0.0105 是混量纲的，除以各自的 SE 才看得出来。
>
> **所以『0 次告警』描述的是我的尺子，不是系统。** 这个实验真正的结论是：
> **我原本选的监控指标看不见这次正类质量下滑，而我把它测出来了。**
>
> 我没有顺手把触发器改成 PR 就宣布修好了——因为按 PR 自身噪声标定出的 δ 比原来那个拍的值**还宽**，它仍然会在 3/6 个窗触发。那 3 次**既不能叫误报**（落差有 5 个 SE 支撑）**也不能叫真告警**（两指标的超量波动比 2.85×/4.64× 说明含真实分布波动，而分布波动和模型退化在这份数据上分不开——没有干预、没有结局标签）。
>
> 真数据只能标定『不误报』这一半，所以我另做了一个**明确标注为构造场景**的合成漂移：把模型分和均匀噪声按强度 α 掺合，用同一次运行标定出的 δ 去检。
> **结果和真数据那半正好相反**：注入纯排序退化时，**ROC 在 α=0.05 就新增 4 个告警、注入当窗即检出，而 PR 新增 0**——要到 α=0.10 才新增 1 个，还延迟 4 个窗。
> 原因有两层：**一是 PR 的 δ 更宽（0.0364 vs 0.0139）恰恰因为 PR 更噪（SE 高 2.6 倍）——噪声大就得放宽阈值，阈值一宽触发器就钝；二是 PR 已经饱和**，注入前它已在 3/6 个窗告警，已经在响的窗不可能再『新增』。
>
> **所以我的结论是『敏感的指标』不等于『敏感的触发器』**——δ 是从噪声里推出来的，一个指标越灵敏地捕捉真实波动，它的 δ 就越宽、触发器反而越钝。
> **这就是我最后没有选定单一触发指标的原因：PR 负责看见，ROC 的触发器负责响，这份数据上任何单一指标都被证明不够。**
> 而合成漂移只能证明检测器在**这一种形态**下的反应——它不是『我经历过真实退化』的证据，也不能外推到『某个子群 P(y|x) 变了』那类真实概念漂移。"*

**这个陈述的四个落点**（缺任一条都会让结论失真）：
1. **测的是尺子，不是系统**——δ 标定 + 噪声归一化，才知道哪个指标有分辨力；
2. **尺子错了要说出来**——"0 告警"作废，不粉饰成"系统稳定"；
3. **两个半边分开测**——真数据只能测误报侧，检出侧必须靠明确标注的构造场景；
