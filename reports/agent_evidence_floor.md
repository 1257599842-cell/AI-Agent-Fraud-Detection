# 把「代码判得了的弃权」前移到管道层

**来历**：剥夺实验（`agent_abstention.md`）证明模型**确实会**在证据被抽干时弃权
（0%→10%→100% 剂量反应）。既然它会，就更该把**结构上可判**的那部分交给代码，
让模型只负责代码判不了的灰区——与「概率判断权归 GBDT」是同一条思路。

实现：`src/agent/pipeline.py::enforce_evidence_floor`，在**校验之前**执行。

## 只做两条，一条都不多

| 规则 | 条件 | 动作 | 为什么它是「代码判得了的」 |
|---|---|---|---|
| **R1** | 账本里**零条标签型事实** | 强制 `evidence_insufficient=true` | 这是关于**证据池**的事实陈述（这单没拿到任何已定案历史），不是对内容的判断 |
| **R2** | 某条 finding **一条 fact 都没引** | 该条 `assertion_strength` 封顶 `tentative` | 无引用即无支撑，与内容无关 |

## 我否掉了自己先前的一条建议

上一轮我写过「无标签型证据 → 置位并**封顶断言强度**」。**实现时否决了后半句**：

> 「本笔金额 $28.04」引 `TXN_000` 标 `confirmed` 是**合法**的——round 4 刚确认
> 「字段值本身可达 confirmed」，这与有没有标签型证据**无关**。
> 按那条改会把对的东西一起降档。

**代码判不了的，就不该让代码判。** 这条纪律对我自己的建议同样适用。

## 绝不静默

每次改写都写进 `pipeline_overrides` 随报告落盘，逐条可查。
本项目已经在**静默替代**上栽过三次（解析器跨块顺延 / M-H 静默跳过缺格 / 兜底顶替缺测），
一个悄悄改写模型输出的管道会是第四次。

|---|---|---|---|
| r1 | 100 | 0 | 0 |
| r3 | 100 | 0 | 0 |

### R1 一次都没触发 —— 这是好消息，不是坏消息

包括**证据被抽干的 E3 档**在内，R1 从未需要出手：E3 的 9 份可解析报告**全部已由模型自己**
置了 `evidence_insufficient=true`。

→ **R1 是安全网，不是补丁。** 它防的是模型哪天不这么做了，而不是在补一个已知缺陷。
（这也与剥夺实验的结论自洽：模型在真没证据时会承认。）

### R2 的 29 条命中呈干净的剂量反应，且全部集中在剥夺臂

| 臂 | E1（掐规则+案例） | E2（再掐实体图） | E3（再掐类别统计） | 四个正常臂 |
|---|---|---|---|---|
| R2 命中 | 2 | 11 | **16** | **0** |

**正常运行下 R2 一条都不触发**；证据越少，无引用断言越多。

### R2 与既有校验器的关系：它加的是**补救**，不是**检出**

`schema.validate_report` 早就把这些标为违规（`evidence_ids 缺失或为空`），29 条里
有 17 份报告已被标出。**R2 不是又发现了什么**——它是把「标出违规」变成「实际降档」：
校验器只说「这条不合规」，报告本身仍在以 `supported` 的强度断言；R2 让下游拿到的那份
报告不再作此断言。

## ⚠️ 由此暴露出的一个更深的缺陷（本文件最值钱的一条）

看 R2 命中的实际内容：

> `E3_starved_3481502` 强度=`supported`、引用=`[]`
> «关联实体无任何历史记录：无历史交易、无扇出、无成熟标签，因此无团伙关联证据。»

**这句话是对的。** 它陈述的是一个**缺席**——工具查了，什么也没返回。

但**缺席在事实登记表里没有表示**：工具返回空时不产生任何 `Fact`，于是
「我查了但没查到」这件事**没有 fact_id 可引**。模型只有两个选择：

1. 不引任何证据地说出来 → 触发校验违规、被 R2 降档（**一个正确的陈述被降档**）；
2. 干脆不说 → 报告里看不出「这里查过且为空」。

→ **R2 在这里做的是对的（无引用就是无支撑），但它惩罚的是一个架构缺陷，不是模型的错。**

### 根因修法（**已于本日实施，见文末追加节**）

让工具在空返回时也登记一条 `null_result` 事实（如
`{type: "null_result", entity: "card1=13526", value: "无历史交易/无扇出/无成熟标签", window: [...]}`），
使**缺席本身可被引用**。这样上面那句话就能正常引证并保持恰当强度。

它**改变证据池**，故与 `policy_param` 上台面**合并为一个独立的「基础设施轮」**执行
（两项都改池，分两轮要付两次跨轮校正的代价）。**结果见文末追加节。**

# 向模型承诺某类证据、而某条代码路径不兑现，得到的不是沉默而是编造

> 这是 v4 这一轮最值钱的产出——**比两项改动本身值钱**。下面先讲它，再讲改动。

## 它是怎么被撞出来的

v4 让「查了但没查到」成为可引用的事实，并在 prompt 里告诉模型：
「工具空返回时也会返回一条事实，缺席陈述请引用它」。

第一次验证时 `null_result` 数是 **0**，模型却**自己编出了 `GRAPH_000` / `RULE_000` 去引用**，
被校验器判为编造（6 条违规）。

原因：验证用的 `StarvedTools`（剥夺实验的工具子类）**覆盖了工具方法却没走父类逻辑**，
空返回没登记事实——**prompt 承诺了，供给没兑现**。

### (a) 模型的行为是**合理**的，不是它的错

它被告知「缺席可以引用」，又**确实需要**陈述缺席（那几句话内容都对），
于是**按命名规律补出一个 ID**。在它的信息集合里，这是唯一能同时满足
「要引证据」和「要说出缺席」两条要求的做法。

**把这记成「模型幻觉」是记错帐了**：诱因在接口，不在模型。

### (b) 与前三次同源

| 次 | 形态 | 表现 |
|---|---|---|
| 1 | 静默替代 | 解析器读不到答案就顺延到下一条 |
| 2 | 静默替代 | M-H 池化静默跳过缺格 |
| 3 | 静默替代 | ⑨ 兜底顶替缺测，把「没测到」变成「测到了」 |
| **4** | **静默失约** | **承诺了某类证据却不给，模型只好自己造** |

前三次是**读不到就顶一个上去**，这次是**承诺了却不给**。
**共同点：接口两侧的约定没有被代码强制，只靠人记得。**

### (c) 由此定下的两条硬规矩

1. **读不到就报缺，绝不顺延。**（`_parse_gold` 漏填即缺席、eval 里降级=缺测不是数据）
2. **承诺了就必须有代码保证兑现。**（凡 prompt 声明「你会拿到 X」，
   所有产生 X 的代码路径都必须实际产出 X；子类覆盖尤其危险）

已修：`StarvedTools` 三个覆盖点统一走 `_empty()`，照常登记 `null_result`。

### (d) 同一条纪律，我也用它否掉了自己的建议

上一轮我自己写过：「无标签型证据 → 置位弃权**并封顶断言强度**」。**实现时否决了后半句。**

理由：`TransactionAmt=$28.04` 引 `TXN_000` 标 `confirmed` 是**合法**的——
round 4 已确认「**字段值本身可达 confirmed**」，这与有没有标签型证据**无关**。
照那条改，会把对的东西一起降档。

> **代码判不了的，就不该让代码判——这条对我自己的建议同样成立。**

所以 `enforce_evidence_floor` 最终只留两条纯结构规则（R1 零标签型事实→强制弃权、
R2 无引用→封顶 tentative），一条都不多。

# 附：两项证据池改动本身（2026-08-01）

按「一次只改一处」的反面——**两项都改证据池，分两轮就要付两次跨轮校正的代价**，
故合并为**一轮**完成，并定位为**基础设施轮，不出任何指标结论**。
`PROMPT_VERSION = v4-citable-context`。

1. **`policy_param` 上台面**：成本假设在每单调查开始时登记为 `POLICY_000`~`POLICY_005`，
   prompt 明示「凡用到成本权衡的论断必须引用相应 POLICY_*」。
2. **`null_result`**：四个工具的空返回路径全部登记事实，让「查了但没查到」可被引用。
   时间窗与 `label_based` 随被查内容原样记 —— **不为它开任何审计豁免**。

## 决定性验证：同一笔交易、同一剥夺档（E3），改前 vs 改后

| | 改前 | 改后 |
|---|---|---|
| `null_result` 事实 | 0 | **6，且全部被引用** |
| schema 违规 | **6 条「引用了未返回的证据 ID（编造）」** | **0** ✅ |
| R2 管道降档 | 2 条 | **0** |
| 成本论断的出处 | 无 | 引用 `POLICY_000` |
| 弃权 / 泄漏审计 | true / 全绿 | true / 全绿 |

改后那两条缺席陈述以 `confirmed` 引用 `GRAPH_000`、`RULE_000`——
**这是对的**：「本笔未命中任何风控规则」是一个**直接检索所得**的事实，
只不过它的内容是「没有」。

## 本轮不出指标结论

证据池变了，`r1`/`r3`/`r4` 的任何数字都**不可与 v4 之后的运行直接比较**。
下一次要出指标，必须在 v4 上重新取基线。**这是本轮定位为「基础设施轮」的含义。**
